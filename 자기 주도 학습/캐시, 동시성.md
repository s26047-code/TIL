# 캐시
#### 데이터베이스나 API 처리 결과를 임시로 저장해두는 데이터 저장소이다.

 이를 활용하면 동일한 데이터 요청 시 원본을 거치지 않고 빠르게 응답할 수 있어 서버의 처리 속도를 높이고 비용 절감이 가능하다.

 이해를 돕기 위해 설명하자면 유튜브에서 인기 영상을 추천해줘 라고 명령하면 그에 맞는 영상을 저장된 DB에서 불러오면 된다.
 
 하지만 몇백만명의 사람이 같은 명령을 내리고, 그에 맞춰 몇번이나 DB를 조회하고 불러온다면? 결국 DB가 터질 수 밖에 없다.

 그러므로 검색하면 바로 나오는 "인기 영상"을 미리 저장해둔다. 이때 이것을 캐시라고 한다.

> #### 장점
> - 캐시는 보통 RAM(메모리)에 있기에 속도가 매우 빠르다.
> #### 단점
> - RAM에 저장하므로 휘발성이다. 데이터가 날아갈 수도 있음

 <br>
 <br>
 

```
캐시가 없을 때

1. 사용자 명령
2. 서버
3. DB 조회 후 불러오기
```

```
캐시가 있을 때

1. 사용자 명령
2. 서버
3. 캐시 확인
4-1. 있을 시 -> 반환 
4-2. 없을 시 -> DB 조회
```

 ## 캐시의 저장소
 #### Redis는 인메모리(In-Memory) 데이터 저장소이다.

Redis는 단순 문자열뿐만 아니라 List, Set, Hash, Sorted Set 등의 다양한 자료구조를 지원한다. 이를 통해 단순 캐시뿐만 아니라 실시간 랭킹, 채팅, 조회수 처리 등 다양한 기능 구현이 가능하다.

예를 들어 실시간 게임 랭킹 시스템에서는 점수 순을 나타내고 싶다면 데이터를 정렬해야 하는데, Redis의 Sorted Set 자료구조를 활용하면 바로 구현 가능하다.

> #### 특징
> - key-value 방식을 사용한다.

#### Memcached 역시 인메모리 데이터 저장소이다.
Memcached는 Redis와 마찬가지로 데이터를 RAM에 저장하여 빠르게 처리할 수 있지만, Redis보다 기능이 단순한 편이다.

Redis와 마찬가지로 데이터를 RAM에 저장하여 빠르게 처리할 수 있지만, Redis보다 기능이 단순한 편이다.

> #### 특징
> - 아주 간단한 key-value 방식을 사용한다.

# 동시성
#### 여러 작업이 동시에 실행되는 환경에서 하나의 자원(Resource)을 함께 사용하는 상황을 의미한다.

예를 들어 수많은 사용자가 동시에 서버에 요청을 보내면 서버는 여러 요청을 한 번에 처리해야 한다.

이때 여러 작업이 동시에 같은 데이터에 접근하게 되면 예상하지 못한 문제가 발생할 수 있다.

이를 동시성 문제(Concurrency Problem)라고 한다.

#### -> 예를 들어 재고가 하나 남은 물건을 동시에 사버리면 생기는 오류

## Race Condition

#### 여러 작업이 동시에 같은 자원에 접근하여 실행 순서에 따라 결과가 달라지는 현상이다.

예를 들어 조회수를 증가시키는 기능에서 동시에 여러 사용자가 요청을 보내면 값이 정상적으로 증가하지 않을 수 있다.

```python
count = count + 1
```

이 코드는 단순해 보이지만 실제로는 아래와 같은 과정으로 동작한다.

```
1. 현재 값 읽기
2. 값 계산
3. 다시 저장
```

만약 여러 요청이 동시에 같은 값을 읽으면 계산 결과가 서로 덮어써져 일부 증가가 누락될 수 있다.

---

> #### 해결 방법
> - Lock 사용
> - synchronized 사용
> - Transaction 적용
> - Redis 분산락 사용

## Lock

#### 동시에 하나의 작업만 특정 자원에 접근할 수 있도록 제한하는 기술이다.

쉽게 말해 한 명씩만 들어갈 수 있는 공간을 만드는 개념이다.

Lock을 사용하면 다른 작업은 현재 작업이 끝날 때까지 기다리게 된다.

---

> #### 장점
> - 데이터 충돌을 방지할 수 있다.
> - 데이터의 정확성을 유지할 수 있다.

> #### 단점
> - 대기 시간이 증가할 수 있다.
> - 잘못 사용할 경우 DeadLock 문제가 발생할 수 있다.

## Transaction

#### 데이터베이스 작업을 하나의 묶음으로 처리하는 기능이다.

작업 도중 문제가 발생하면 이전 상태로 되돌릴 수 있다.

예를 들어 계좌 이체 기능은 다음 두 작업이 반드시 함께 실행되어야 한다.

```
A 계좌 -5000
B 계좌 +5000
```

만약 첫 번째 작업만 실행되고 서버가 종료된다면 데이터 오류가 발생하게 된다.

따라서 모든 작업이 성공하면 Commit, 실패하면 Rollback을 수행한다.



> #### 특징
> - 데이터 일관성을 유지할 수 있다.
> - 작업 실패 시 이전 상태로 복구 가능하다.
> - 안정적인 데이터 처리가 가능하다.

## DeadLock

#### 서로 다른 작업이 상대방의 작업이 끝나기를 기다리며 무한 대기 상태에 빠지는 현상이다.

예를 들어:

```
A 작업 → B 자원 기다림
B 작업 → A 자원 기다림
```

이 경우 두 작업 모두 영원히 종료되지 못한다.



> #### 해결 방법
> - Lock 순서를 통일한다.
> - Lock 사용 시간을 최소화한다.
> - Timeout을 설정한다.
