# 프록시 객체
특정 실제 객체를 대신해서 호출을 받고, AOP 같은 부가 작업을 한 뒤 그 실제 객체로 호출을 전달하는 **대리 객체**이다.

 여러 기능들에 공통 기능을 한번에 호출하고 싶은데, 각 서비스는 모두 다르고 나는 코드를 요약해서 쓰고 싶다.

 그러니 그 객체들을 **대신하여 호출해주는 대리인**인 역할을 해준다


 <br>
 
 또한 만약 프록시 객체를 사용하지 않는다면 **연관관계가 걸려 있는 것을 모조리 끌어와 DB 부하**에 걸릴 수 있다는 문제가 생긴다.

 그러므로 JPA는 프록시를 두고, 쿼리를 날려서 데이터를 가져오는 방식으로 진행된다.

## 프록시의 생성 방식
프록시 객체의 생성 방법은 대표적으로 두 가지가 있다. 

<br>
<br>


### JDK Dynamic Proxy
인터페이스 기반으로 프록시 객체를 만드는 것으로, 우리가 자주 사용하는 `@Transactional` 같은 기능을 붙일 때 인터페이스가 있다면 이 방식을 사용하게 된다.

<br>

예시 코드를 봐보자.
```gradle
OrderService proxy = (OrderService) Proxy.newProxyInstance(
    OrderService.class.getClassLoader(),
    new Class[]{OrderService.class},
    new InvocationHandler() {
        @Override
        public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
            System.out.println("트랜잭션 시작");
            Object result = method.invoke(realService, args);
            System.out.println("트랜잭션 종료");
            return result;
        }
    }
);
```

**인터페이스가 어디 있냐고 할 수도 있는데, 바로 
`InvocationHandler` 부분이 인터페이스이다.**

 `new InvocationHandler() { ... }`는 해당 인터페이스를 구현한 <makr>익명 클래스의 객체를 생성하는 문법</mark>이라고 한다. 생성한 객체를 변수에 저장할 수도 있고, 현재 `코드처럼 Proxy.newProxyInstance()`의 인자로 바로 전달할 수도 있다.

 <br>
 <br>

### CGLIB Proxy
위의 JDK와 반대로 **클래스를 상속하여 프록시 객체**를 만든다. 만일 인터페이스를 구현하지 않았다면, CGLIB 라이브러리를 이용해 프록시를 만든다고 한다.

그래서 이 프록시 생성 방식을 사용한 객체의 클래스명은 대부분 `$$EnhancerByCGLIB$$` 같은 코드가 붙어있는 것을 확인할 수 있다.

```gradle
class OrderService$$EnhancerByCGLIB$$12345 extends OrderService {
    @Override
    public void placeOrder() {
        // 트랜잭션 열기
        super.placeOrder();
        // 트랜잭션 닫기
    }
}
```

## 실제 동작 흐름
이렇게 설명하면 상당히 멀게 느껴지나, 생각보다 프록시는 훨씬 일반적으로 사용되고 있다.

프록시가 사용된 예시 엔티티 코드를 봐보자.

```gradle
@Entity
@Table(name = "posts")
@Getter
@NoArgsConstructor
public class Post {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @ManyToOne(fetch = FetchType.LAZY) // ← 프록시 객체 생성
    @JoinColumn(name = "user_id", nullable = false)
    private User user;

    @OneToMany(mappedBy = "post", fetch = FetchType.LAZY) 
    private List<Comment> comments = new ArrayList<>();

    private String title;
}
```
`@ManyToOne`에 붙어있는 `fatch = FatchType.Lazy`를 살펴보자.

 `fetch`는 연관된 데이터를 언제 가져올지 정하는 설정이며, `lazy`는 그 방식, 즉 <mark>지연 로딩</mark>을 의미하고 있다.

> ## <span style="color: gray;">지연로딩이란?</span>
>
> <span style="color: gray;">연관된 엔티티를 처음에는 조회하지 않고, 실제로 해당 엔티티가 필요한 시점에 조회하는 방식이다.</span>

<br>

 즉, 그러니 이 코드는 유저 객체를 바로 불러온 것이 아닌, **프록시가 DB 조회를 실행하고 진짜 User로 교체되는 지연로딩으로 작성**되었다는 것이다!

 이런 자연스러운 과정에도 프록시가 들어있었다.
