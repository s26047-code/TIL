# OAuth 방식이란?
**사용자의 개인정보를 보호 하기위해 실제 비밀번호를 받는 것이 아닌 <mark>해당 플랫폼에서의 인증</mark> 증표를 받아 인증하는 방식이다.**

즉, 인증이 되었다는 사실을 위임받아 로그인 기능을 돕는 것이다.

<br>
<br>


### 이를 가능하게 하는 클래스로는 OAuth2SuccessHandler가 있다.

**구글 로그인이 성공적으로 끝나면, Spring Security를 별도의 인증 없이 자동으로 실행** 해주는 원리로 작동된다.

`Spring Security`에는 `OAuth2 Client`라는 내장된 기능이 존재하는데, 리다이렉트 주고받고 구글이랑 통신하는 복잡한 과정 <span style="color: gray;">(Authorization Code 교환, Access Token 받기, 사용자 정보 조회하기)</span> 을 전부 프레임워크가 알아서 처리해주는 기능이다.

이 기능을 사용하면 인증은 끝이나며, **인증 후 활동을 지정**<span style="color: gray;"> (신규 유저라면 계정 생성하는 클래스를 불러오거나, 이미 있는 유저라면 계정 정보를 가져오는 클래스를 불러오는 등의 활동) </span> 하는 클래스가 바로 OAuth2SuccessHandler라고 할 수 있다.

# 인증 방식

### 쿠키
쿠키란 **서버가 사용자의 정보를 담아 그대로 전달**하는 방식이다.

하지만 쿠키는 브라우저 개발자 도구 등으로 값을 그대로 확인하고 조작할 수 있어 보안 문제가 있었다. 그러므로 그것을 보완하여 나온 것이 <mark>세션</mark>이다.

<br>
<br>

### 세션
세션이란 쿠키의 단점을 보완한 방식으로, 쿠키는 정보를 그대로 전달했다면
세션은 **쿠키에는 의미 없는 문자열(세션 ID)만 담고, 진짜 정보는 서버에
저장해둬 비교하여 인증**하는 방식이다.

하지만 세션은 서버가 모든 사용자를 직접 저장하고 있어야 하는
구조라, 서버가 늘어나면 세션을 공유하기 위한
별도 저장소가 필요해지는 등 서버의 부담이 커지게 된다. 이를 해결하기 위해 나온 방식이 <mark>토큰</mark>이다.

<br>
<br>

### 토큰
토큰이란 쿠키·세션처럼 서버가 사용자 상태를 저장하는 대신, **인증에
필요한 정보와 그 정보가 위조되지 않았음을 증명하는 서명을 클라이언트가
직접 들고 다니는 방식**이다. 이때 서버는 별도의 저장소를 조회할 필요 없이
서명만 검증하면 되기 때문에 서버의 부담이 줄고, 확장이 쉽다는 장점이 있다.

이때 토큰 방식의 대표적인 방식이 바로 <mark>JWT</mark>이다.

<br>
<br>

## JWT
토큰은 사용자의 정보, 서명, 인증을 전부 확인해야 하지만, JWT 방식은 **발급받은 토큰의 서명이 유효하다면 별도의 서버 조회 없이 인증**된 요청으로 처리된다는 장점을 가진다.

단, 한번 발급된 토큰은 유효시간이 지나기 전까지 강제로 삭제하거나
무효화할 수 없다. 그래서 로그아웃을 하더라도 이미 발급받은 토큰이 있다면 관련 API 요청이 그대로 통과되어 버리는 단점 역시 존재한다.


<br>
<br>

**JWT는 3가지의 구조로 이루어져 있다.**

| 구분 | 역할 |
|---|---|
| **Header** | 토큰 타입과 암호화 알고리즘 정보 |
| **Payload** | 실제 담을 데이터 (사용자 ID, 권한 등) |
| **Signature** | 위·변조 방지를 위한 서명값 |

ㄴ> 단, Payload는 Base64로 인코딩된 것일 뿐 암호화가 아니기 때문에 비밀번호 같은 민감한 정보는 담으면 안 된다. <br>
- base64란 이진 데이터 텍스트로 변환하는 인코딩 방식이다!

# 알게 된 점
이번에 공부하며 `Refresh Token`은 평소 구현하던 `Access Token`이 만료되었을 때를 대비해 새로운 `Access Token`을 발급받아 갱신하기 위해 사용하는 토큰이라는 것을 알게 되었습니다. 이부분은 평소에도 궁금증을 가지고 있던 부분인지라 궁금증을 해결할 수 있었고, 사용자가 매번 다시 로그인하지 않아도 인증을 유지할 수 있는 이유를 이해할 수 있게 되었습니다.

또 key라는 라이브러리 내장 함수가 있어서 더 편리하게 토큰 반환을 할 수 있다는 부분도 새롭게 알게 되었습니다.

<br>
이번 과제를 해결하며 처음으로 외부에서 정보를 받아오는 로그인 방식을 구현했는데, 평소에도 궁금증을 가지고 있던 OAuth 방식에 대해 공부할 수 있어 좋았던 것 같습니다.
